# SlotMem Delta-8 Hard-Scene Experiment Design

Date: 2026-08-21

## Goal

Replace the low-sensitivity `sample_5` library event with a controlled character-reappearance event that requires long-range identity memory. The experiment must distinguish memory utility from ordinary adjacent-frame continuation.

## Frozen Story

Reuse the existing story in `utest/events/person_reappearance_delta8_story.json`; do not create a second prompt format or duplicate the story.

- Source character: `Mara`.
- Source chunk: `0`.
- Prefix chunks: `0` through `7`.
- Target chunk: `8`.
- Mara appears clearly in chunk 0, is absent from chunks 1 through 7, and first reappears in chunk 8.
- The intervening story changes location, lighting, camera composition, motion, occlusion, and co-occurring characters.
- Chunk 2 contains a deliberately similar auburn-haired distractor, while chunk 8 returns Mara from a high three-quarter angle in a dynamic crowd scene.

The matching event contract is `utest/events/person_reappearance_delta8.json`.

## Scientific Comparison

The independent variable remains the target-step memory arm:

- `correct`: Mara's frozen prefix memory.
- `correct_repeat`: deterministic repeat of `correct`.
- `no_memory`: no character memory.
- `zero`: shape-matched zero memory.
- `random`: shape-matched random memory.
- `wrong`: a compatible donor character memory with frozen provenance.
- `native`: normal unmodified SlotMem rollout.

All target arms must share the same prefix, target prompt, teacher video, target noise, and inference configuration. Only the memory intervention may differ.

Primary interpretation is based on the Q* teacher-forced probe. Free rollout remains a validation of visible downstream effects, not the definition of Q*.

## Data Flow

1. Generate or supply a fixed initial reference image for Mara in chunk 0.
2. Generate chunks 0 through 7 once with the frozen story prompts.
3. Freeze the prefix videos, final prefix frame, SlotMem state, inference arguments, platform manifest, and prefix contract.
4. Independently generate the held-out chunk-8 teacher video from the frozen target prompt and its own provenance manifest. It must not be generated by any evaluated arm.
5. Prepare a compatible wrong-character donor payload and matched-pair manifest.
6. Run `scripts/run_slotmem_qstar_event.sh` against a fresh output directory.
7. Validate the seven arms, Q* report, provenance manifests, and deterministic repeat.

The completed `sample_5` run remains untouched as the low-difficulty same-scene control.

## Required Changes

Use the existing story and event JSON files. Only add or change the minimum configuration or helper material needed to make the delta-8 event runnable on the cloud host. Do not modify generated artifacts under `runs/qstar_sample5_debug_20260820_182243`.

The cloud launch instructions must bind:

- `EVENT_JSON` to `utest/events/person_reappearance_delta8.json`.
- `FUTURE_TARGET_VIDEO` and `FUTURE_TARGET_MANIFEST` to the independent chunk-8 teacher assets.
- `BASE_INFERENCE_ARGS` and `PLATFORM_MANIFEST` to frozen host-specific files.
- `DONOR_PAYLOAD` and `DONOR_MANIFEST` to a compatible wrong-character donor.
- `EVENT_RUN_ROOT` to a new, nonexistent output directory.

## Failure Conditions

Fail before GPU generation if any of the following holds:

- Mara appears in a prefix character list after chunk 0.
- The target is not chunk 8 or Mara is absent from its character list.
- The teacher video or manifest is missing or shares provenance with an evaluated arm.
- The donor is incompatible with the target memory schema.
- The output directory already exists.
- The source tree is dirty unless explicitly allowed for development.

## Verification

The smallest runnable preflight must verify:

- story indices are contiguous from 0 through 8;
- Mara is present only in chunks 0 and 8;
- source/target indices and character name agree between story and event JSON;
- existing content, Q*, and input-contract self-checks pass;
- a dry run resolves the expected event, prefix, teacher, donor, and seven arm commands without launching generation.

Success does not require SlotMem to win. A scientifically valid negative result is acceptable if the event contract, interventions, teacher provenance, and Q* computation are valid.
